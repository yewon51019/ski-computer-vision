## DEV-03 · MoveNet Thunder v4 기본 성능 (독립 실험)

2026-11-16 · Windows 10, Python 3.12.10, TensorFlow 2.21.0(CPU), NumPy 2.5.5, pandas 3.1.1, Pillow 13.0.0. 가상환경 .movenet-venv에서 nbconvert로 노트북 전체를 실행했고 오류 없이 끝났다(약 19분, 같은 PC의 다른 실행과 CPU를 나눠 썼다). 모델은 Kaggle google/movenet tensorFlow2 singlepose-thunder 4의 SavedModel이다(saved_model.pb SHA-256 ea126ce61a8d11321a5523a5f0b07bb22184a848d193df7a5d0a42068f0ac15f, 입력 1×256×256×3).

## DEV-03 · MoveNet Thunder v4 영상 기준 성능 (독립 실험)

EPFL 원본 영상 158개 구간(33,369프레임, 1920×1080 118개·1280×720 40개, 대부분 25fps)을 순서대로 읽어 추론하고, 정답이 있는 1,982프레임에서 수동 좌표와 비교한다. 채점 규칙은 사진 평가와 같다(점수 0.30, 좌우는 모델 출력 그대로, 크기 그룹 동일). 스크립트는 movenet_video_eval.py(추론·채점)와 movenet_video_post.py(누락 메우기·흔들림 완화)다.

방식

- 화면 전체: 사진 평가와 같은 입력. 정답 프레임에서만 실행.
- 추적: 앞 프레임 관절로 다음 프레임의 입력 영역을 정한다(MoveNet 공식 예제의 자르기 규칙). 구간 시작과 몸통을 놓쳤을 때는 화면 전체로 돌아간다. 모든 프레임에서 실행.
- 추적+카메라 보정: 스키어 영역 밖 배경의 특징점으로 프레임 간 이동·확대·회전을 추정하고(가로 480px 축소 화면), 그만큼 입력 영역을 옮긴다.
- 누락 메우기: 굽힘량이 0.2초 이하로 끊기고 양쪽이 검출된 구간만 직선으로 잇는다.
- 흔들림 완화: 메운 뒤 앞뒤 0.2초 구간의 중앙값.

2026-11-16 · Windows 10, GTX 1070 Ti, 환경 .movenet-gpu(Python 3.10.22, TensorFlow 2.10.1, CUDA 11.2, OpenCV 4.11.0). 전체 실행 22.2분, 추적 두 방식을 함께 돌려 프레임당 39.9ms. 오류 없이 끝났다.

정답 프레임 1,982장 기준

| 방식 | 양쪽 무릎 검출 | 검출률 | 왼쪽 MAE (비교 쌍) | 오른쪽 MAE (비교 쌍) | 무릎 위치 맞음 |
|---|---|---|---|---|---|
| 화면 전체 | 580 | 29.3% | 25.1° (748) | 25.6° (757) | 69.4% |
| 추적 | 1,174 | 59.2% | 13.7° (1,261) | 14.6° (1,217) | 88.0% |
| 추적+카메라 보정 | 1,104 | 55.7% | 14.9° (1,194) | 15.3° (1,138) | 86.3% |
| 추적 + 누락 메우기 | 1,549 | 78.2% | 14.8° (1,485) | 15.5° (1,440) | |
| 추적 + 메우기 + 흔들림 완화 | 1,549 | 78.2% | 14.4° (1,485) | 14.8° (1,440) | |

"무릎 위치 맞음"은 검출된 다리 중 예측 무릎이 정답 무릎에서 몸통 길이의 절반 이내인 비율이다.

- 크기별(추적): 큰 그룹 66.6%, 왼쪽 11.0°·오른쪽 14.7°. 작은 그룹 53.5%, 왼쪽 17.1°·오른쪽 14.5°. 메우기와 완화 후에는 큰 그룹 85.8%, 작은 그룹 72.3%.
- 전체 프레임 보류율(추적): 33,369프레임 중 양쪽 무릎 검출 16,530프레임(49.5%), 메우기 후 69.6%. 입력이 화면 전체로 돌아간 프레임은 3,083프레임(9.2%).
- 오차 분포(추적): 중앙값 7.2°, 10° 이내 61.9%, 45° 초과 7.1%. 모델 굽힘량이 정답보다 평균 6.9° 작다(중앙값 2.4°). 화면 전체 입력의 평균 17.9°보다 치우침이 작다.
- 메워 넣은 값의 오차는 20.7°(447쌍)로 직접 검출된 값보다 크다. 메우기는 검출률을 올리지만 평균 오차를 약 1° 올린다.
- 흔들림 완화: 프레임 간 굽힘량 변화가 평균 7.2°에서 3.3°로 줄고 MAE는 약 0.5° 줄었다.
- 카메라 보정은 검출률을 3.5%p 낮췄다. 중계 카메라가 스키어를 따라가 스키어는 화면의 같은 자리에 있고 배경이 움직이므로, 배경 이동만큼 영역을 옮기면 스키어에게서 멀어지는 것으로 보인다(원인은 확인하지 않았다). 아래에서 손으로 찍는 영상에서는 결과가 다를 수 있으나 그런 영상이 없어 미검증이다. 카메라 움직임은 33,369프레임 중 33,210프레임에서 추정됐고 프레임별 값은 data/movenet_video_allframes.csv에 있다.

확인

- 프레임 번호: 정답 사진 1,982장 모두 정답에 적힌 번호의 영상 프레임과 가장 잘 일치했다. 영상에 없는 정답 프레임은 없다.
- 정답 굽힘량, 크기, 그룹이 사진 평가(movenet_frames.csv)와 1,982장 모두 같다.
- 화면 전체 방식의 영상 결과는 사진 결과와 가깝다(양쪽 무릎 580장 대 569장, 다리별 검출 여부 일치 약 88~89%, 굽힘량 차이 중앙값 약 2°). 영상 프레임과 WebP 사진의 화질 차이로 같지는 않다.
- 확인용 그림 1장에서 추적 영역이 스키어를 감싸고 추적 결과가 정답 다리와 겹치는 것을 눈으로 확인했다.

변경 파일: movenet_video_eval.py, movenet_video_post.py(신규), movenet_video_frames.csv·movenet_video_sequences.csv·movenet_video_summary.csv·movenet_video_post_summary.csv(신규), TASKS.md, HANDOFF.md, 이 문서. 영상과 프레임별 결과는 data/에 있고 Git에서 제외했다.

## DEV-07 2단계 · 24점 모델(YOLO11m-Pose) 평가

2026-11-17 · ski24_dataset.py로 만든 잘라 낸 그림(정답 24점 상자 ×1.3 정사각형)으로 YOLO11m-Pose를 학습했다(ski24_train.py: 512px, 150회 전부 진행, GTX 1070 Ti에서 약 2.5시간, 마지막 검증 pose mAP50 0.88). 평가는 학습·검증에 쓰지 않은 5개 영상의 정답 프레임 495장(ski24_eval.py). PCK는 점을 찾았고(ski24 점수 ≥ 0.5, MoveNet ≥ 0.3) 정답과의 거리가 스키어 키(정답 점의 세로 범위)의 5%·10% 이내인 비율이며, 분모는 정답에서 '보임'인 점이다. 자르기는 두 가지다. truth는 정답 상자로 잘라 가장 좋은 경우를 보여 주는 참고값이고(앱에서는 불가능), detected는 사람 검출 상자 ×1.5로 잘라 앱과 같은 조건이다.

| 부위 | ski24 truth | ski24 detected | MoveNet truth | MoveNet detected |
|---|---|---|---|---|
| 몸 12점(어깨·팔꿈치·손·골반·무릎·발목) | 찾음 100%, PCK 47/76% | 99%, 46/72% | 84%, 52/73% | 86%, 53/73% |
| 머리·목 | 98%, 79/95% | 97%, 78/90% | 없음 | 없음 |
| 폴 끝 | 100%, 2/9% | 99%, 2/5% | 없음 | 없음 |
| 스키 앞·뒤 끝 | 100%, 33/69% | 98%, 29/55% | 없음 | 없음 |
| 발끝·뒤꿈치 | 100%, 64/89% | 99%, 63/84% | 없음 | 없음 |

점별 PCK 10%(detected 기준): ski24가 앞선 점은 무릎(79·77% 대 72·69%)과 발목(83·87% 대 72·73%). MoveNet이 앞선 점은 팔꿈치(64·60% 대 77·72%)와 손(37·34% 대 54·48%). 폴 끝은 6·5%.

무릎 굽힘 오차(두 모델이 모두 잰 다리만): truth 652개 다리에서 ski24 평균 16.5°(중앙값 11.8°), MoveNet 11.7°(6.6°). detected 684개 다리에서 ski24 16.6°(11.3°), MoveNet 12.0°(7.0°). ski24는 다리를 더 많이 찾지만(detected 819개 대 684개) 각도는 MoveNet이 더 정확하다.

폴 끝 확인: 오차 중앙값이 키의 37~46%로 사실상 맞히지 못했다. 좌우를 바꾸면 오차가 더 커져(중앙값 97~99%) 좌우 뒤바뀜이나 점 순서 오류는 아니다. 정답과 예측을 그림 위에 그려 보면 폴은 가늘고, 몸 뒤로 넘어가거나 눈 위에서 잘 안 보이는 장면이 많다. 학습 1,187장(영상 10개)으로는 배우지 못한 것으로 판단한다.

- 판단 보류: 채택 여부는 사용자가 정한다(TASKS DEV-07).
- 미검증: 512px보다 큰 입력이나 더 많은 학습 자료로 폴 끝이 나아지는지는 시험하지 않았다.

손촬영 영상 확인(2026-11-18): 웹 2단계용 ski24_analyze.py(고른 사람 상자 ×1.5로 자르기, 상자 없는 프레임은 직전 점 ×1.3으로 따라가기)를 손촬영 2편(20초 영상 추적 93, 61초 영상 추적 40)에 돌렸다. 분석 구간(1.7초·2.5초)과 양쪽 무릎 100%는 MoveNet과 같고, 한 편 처리에 11~15초(GTX 1070 Ti). 분석 구간 안 무릎 굽힘의 두 모델 차이는 평균 7~14°(중앙값 3~15°)다. 같은 프레임 4장씩을 그려 보면 MoveNet은 몸 선이 스키어 위에 잘 겹치는데, ski24는 뒷모습에서 다리 좌우가 X자로 엇갈리거나 카메라에 가까워진 장면에서 몸 선이 크게 벗어났다. 스키 선은 옆모습 영상에서 스키 위에 대체로 겹쳤다. 정답이 없어 어느 쪽 각도가 맞는지는 수치로 모르지만, 눈으로는 몸·무릎은 MoveNet이 낫다.
