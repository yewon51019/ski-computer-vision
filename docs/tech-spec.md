# 스키 자세 코칭 기술설계 초안

## 첫 구현과 화면 경계

React + Vite 단일 페이지 앱을 루트에 구성한다. 첫 구현은 정적 페이지 셸과 탐색이다. 제안한 경로는 홈(/), 주행 분석(/analysis), 분석 결과(/results)이며, 알 수 없는 주소에는 홈으로 돌아갈 링크를 둔다. 브라우저의 링크·뒤로 가기·직접 진입을 지원한다. 배포 시 호스트에 SPA fallback이 필요하다. 첫 작업에서 데이터 전송과 모델 호출은 없다.

## 후속 영상 처리 설계

| 단계 | 입력 → 출력 | 판정·복구 조건 |
|---|---|---|
| 디코딩 | 영상 → 재생 시간(ms), 원본 너비·높이, 프레임 | 가변 프레임률은 실제 표시 시각 사용. 끊김·컷에서 추적 상태 초기화 |
| 사람 추적 | 프레임 → 스키어 기준 좌우 관절, 점별 신뢰도 | 사전학습 Pose Landmarker를 첫 비교 후보로 사용. 모델·버전 기록. EPFL 장비 점과 인체 모델 점은 별도 취급 |
| 무릎 굽힘 | 골반·무릎·발목 → 화면상 굽힘(도) | 좌표를 원본 픽셀로 환산. 180°에서 내각을 뺌. 가림·겹침·영벡터는 해당 다리 보류 |
| 카메라 움직임 | 스키어 밖 배경의 대응점 → 프레임 간 전역 변환 후보 | 배경 특징이 부족하거나 컷이면 보정 신뢰도 낮음. 화면 속 좌우 이동만으로 턴 확정 금지 |
| 턴과 리듬 | 보정 경로와 몸통 대비 발의 좌우 변화 → 전환 후보, 구간, 전환 간격(초) | 신호가 지속되고 교대로 나타나는지 확인. 숏턴 분류 기준은 수동 라벨로 조정. 긴 누락 구간을 이어 붙이지 않음 |
| 상체·팔 | PRD의 특징점 → 항목별 값, 관찰 가능 여부 | 정면 전후 위치 보류. 팔꿈치 굽힘과 위팔 벌림은 독립 평가. 너비 분모가 작거나 손이 가려지면 필요한 지표만 보류 |
| 코칭 | 턴 단계·측정값·시점·승인된 규칙 → 시간 범위와 행동 문구 | 관찰값과 교정 권고를 구분. 규칙 ID·판정 사유·근거 시간 보관. 승인 전 수치로 행동 권고를 생성하지 않음 |

분석 결과의 최소 단위는 주행 ID, 원본 시간 범위, 해부학적 좌우, 지표 이름·단위·값, 상태(측정/보류) 및 사유다. 보류 값은 빈 값으로 유지한다. 재생 시각과 같은 시간축으로 오버레이와 피드백을 연결한다.

## 기준 자료와 결정 시점

EPFL 수동 좌표는 프레임 단위 각도 검증에 사용한다. 경기 해설을 쓰려면 대회·선수·주행 차수·기문 또는 중간기록으로 동일 턴을 확인하고, 양쪽 영상의 시각과 실제로 언급한 부위를 기록한다. 일치하지 않는 해설은 자세 라벨에서 제외한다. 경험자는 교정·유지·보류와 문구를 검토한다.

2026-11-16 사용자 결정: 처음에는 혼자 쓰지만 다른 사람도 접속할 수 있는 웹 구조로 만든다. 분석은 GPU가 있는 PC의 FastAPI 서버에서 한다. 웹 DB는 쓰지 않고 영상과 결과는 쓰는 기기(컴퓨터 또는 휴대폰)에 둔다. 결과는 다시 인코딩한 영상이 아니라 원본 영상 위에 브라우저가 관절선을 그려 보여 준다. 스키어가 작게 보이는 구간은 보류하며 기준은 검출 상자 높이 80px다. 화면에 여러 사람이 있으면 사용자가 분석할 스키어를 클릭해 고른다(자동 선택은 하지 않는다). 그래서 분석은 두 단계다: 사람 찾기와 이어 붙이기(person_tracks.py) 후 후보를 보여 주고, 고른 한 명만 관절을 추정한다(ski_analyze.py). 두 단계는 ski_pipeline.py가 실행한다. 이 결정으로 PRD의 "사용자가 관절이나 턴을 지정하지 않는다"에 스키어 선택 한 번이 예외로 추가된다. 미결정: 파일 크기·길이 한도, 서버가 받은 영상을 분석 후 지우는지. 첫 촬영 조건에서 검증 후 추적 촬영으로 확장한다. 현재 분석된 자료는 정지 이미지와 수동 좌표이며, 연속 MP4 및 동기화된 해설 사례는 미확보 상태다.

## 스키·폴까지 24점 관절 모델 (DEV-07 2단계)

2026-11-17 사용자 결정: 스키·폴 끝점을 얻기 위해 YOLO11m-Pose(ultralytics, AGPL-3.0)를 EPFL Ski-2DPose 24점으로 추가 학습한다. 공개 서비스로 갈 때나 정확도가 부족할 때의 두 번째 후보는 RTMPose(MMPose, Apache-2.0)다. 선행 연구는 HRNet 계열과 AlphaPose를 썼다.

| 항목 | 내용 |
|---|---|
| 점 순서 | EPFL 순서 24점: 0 머리, 1 목, 2~5 오른쪽 어깨·팔꿈치·손·폴 끝, 6~9 왼쪽 어깨·팔꿈치·손·폴 끝, 10~12 오른쪽 골반·무릎·발목, 13~15 왼쪽 골반·무릎·발목, 16~19 오른쪽 스키 앞끝·발끝·뒤꿈치·스키 뒤끝, 20~23 왼쪽 스키 앞끝·발끝·뒤꿈치·스키 뒤끝 |
| 입력 | 화면 전체가 아니라 스키어 주변을 잘라 넣는다. 학습은 정답 24점을 감싸는 상자를 넓혀 자르고, 앱과 평가에서는 사람 검출 상자를 넓혀 자른다 |
| 데이터 분할 | 같은 영상의 프레임은 서로 거의 같으므로 영상 단위로 학습·검증·평가를 나눈다(고정 시드) |
| 평가 | 평가용 영상에서 점별 검출률, 정답 상자 높이 대비 위치 오차(PCK), 무릎 각도 오차. 같은 잘라 넣기로 MoveNet과 비교 |
| 채택 | 2026-11-18 사용자 결정: 섞어 쓰기. 몸 17점과 무릎 수치는 MoveNet, 스키·발 8점(16~23번)만 이 모델에서 가져온다(손촬영 영상에서 몸·다리는 MoveNet이 더 잘 맞음). 폴 끝은 쓰지 않는다. ski_pipeline.analyse가 ski24_analyze.py(.yolo-venv) → ski_analyze.py --skis(.movenet-gpu) 순서로 돌려 result.json의 frames.skis에 붙이고, 화면은 스키·부츠 바닥 선을 몸 선과 잇지 않고 그린다. 두 환경을 하나로 합치는 것(MoveNet ONNX 변환)은 나중 작업 후보 |
| 확인할 것 | EPFL 데이터의 사용 조건(연구용)에서 학습한 모델을 공개 서비스에 쓸 수 있는지 |
