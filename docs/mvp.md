## 첫 시연의 완료 조건

아래에서 촬영한 한 명의 연속 주행 영상을 올린다. 방향이 고정된 손촬영 영상에서 좌우 무릎 굽힘을 확인하고, 숏턴 구간과 리듬을 따라가며, 검토된 교정 대상 장면에서 행동 지침을 읽고 해당 구간을 다시 볼 수 있어야 한다. 결과를 미리 입력해 둔 예시 영상만 재생하는 데모로는 완료되지 않는다.

| 순서 | 포함할 결과 | 확인 방법 |
|---|---|---|
| 1. 무릎 굽힘과 코칭 | 다리별 관절선·각도, 구간에 연결된 교정 문구, 측정 또는 교정 보류 상태 | 라벨 프레임에서 각도를 대조한다. 검토자가 고른 교정 대상 장면에서 구간·근거·동작 지침이 일치하는지 확인한다. |
| 2. 숏턴 구간 | 연속 숏턴의 시작·끝, 그 안의 개별 턴 전환 시점 | 사람이 표시한 연속 영상과 대조하고, 긴 턴을 숏턴으로 표시한 사례도 기록한다. |
| 3. 리듬 | 전환 간 시간과 구간 재생 | 영상 시각과 표시값이 일치하는지 확인한다. 잘린 턴이나 추적 손실 구간에서는 시간을 추측하지 않는다. |

첫 시연의 자세 코칭 범위에는 머리·상체의 전후 위치와 폴을 든 팔의 손 높이·팔꿈치 굽힘·위팔 벌림·양손 너비도 포함한다. 구현·검증은 무릎 굽힘부터 시작한다. 한 주행에서 정면으로 접근하는 구간은 팔 높이와 너비, 비스듬히 지나가는 구간은 상체 전후 위치를 확인할 후보가 된다. 각 구간에서 실제로 보이는 부위만 평가한다. 팔꿈치 굽힘만 교정할 장면과 위팔 벌림만 교정할 장면을 경험자가 각각 선정한다. 두 사례에서 해당 동작의 문구가 독립적으로 표시되는지 확인한다.

전신 코칭의 시연 자료에는 항목별로 경험자가 교정이 필요하다고 표시한 장면, 자세를 유지해도 되는 장면, 가림이나 촬영 방향 때문에 판단할 수 없는 장면을 포함한다. 같은 장면에 모든 조건을 담을 필요는 없다. 검토된 사례와 비교해 교정 문구와 보류 사유가 맞는지 확인한다. 시연 자료가 없는 항목은 미검증으로 기록한다.

## 시연 자료와 검증 순서

1. EPFL 원본 MP4에서 아래쪽 촬영 조건에 맞고 여러 턴이 이어지는 클립을 고른다. 현재 작업 폴더에서 확인된 입력은 WebP·JSON ZIP이다. 후보 MP4와 교정 시범 구간은 아직 선정되지 않았다.
2. 시범 클립에 턴 전환 시각, 비교할 턴 단계, 교정 또는 보류 사유를 기록한다. 점검할 대상 주행과 기준 동작을 구별한다. 무릎 각도 계산은 기존 정답 좌표 결과와 재검증한다.
3. 별도 주행을 실제 업로드 경로로 분석한다. 손떨림, 다리 겹침, 스키어가 멀리 있는 구간, 숏턴이 없는 구간까지 확인한다. 제대로 측정한 장면만 골라 정확도를 보고하지 않도록 전체 구간의 보류율도 함께 기록한다.
4. 추적 촬영은 첫 시연이 통과한 뒤 별도로 검증한다. 추적 촬영 샘플 수집과 공통 화면 설계는 병행할 수 있다.

## 구현으로 넘어갈 때

이번 산출물은 PRD와 MVP 문서다. 사용자가 제시한 저장소 구조에 맞춰 후속 단계에서 README.md, AGENTS.md, TASKS.md, docs/problem.md, docs/tech-spec.md, docs/test-plan.md 및 src/를 정리한다.

첫 구현 범위는 **DEV-01 · React + Vite 프로젝트와 기본 라우팅**이다. 시작 전 AGENTS.md, docs/prd.md, docs/tech-spec.md, TASKS.md를 읽고 실제 프로젝트 구조를 확인한다. 필요한 문서가 아직 없으면 먼저 명세를 갖춘다. TASKS.md에서 DEV-01 하나를 선택하고 경로·변경 계획을 먼저 확인한다. 이 작업에는 Supabase 연결, 영상 업로드, 분석 모델, 실제 코칭 기능이 포함되지 않는다.

구현 후 실행·lint·build·관련 테스트 결과, 변경 파일, 수용 기준별 실제 동작과 미검증 항목을 기록한다. 검증 후 다음 작업으로 진행하며 요구사항이 바뀌면 관련 문서를 먼저 갱신한다.
